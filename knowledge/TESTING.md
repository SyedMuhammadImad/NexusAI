## Evidence Levels

- `SOURCE_PRESENT`: implementation exists; not enough for completion.
- `UNIT_VERIFIED`: bounded logic passes deterministic tests.
- `INTEGRATION_VERIFIED`: interacting components pass end-to-end fixture tests.
- `FAULT_VERIFIED`: crash/retry/replay/concurrency behavior passes controlled fault tests.
- `BROKER_DEMO_VERIFIED`: behavior reconciles to attested MT5 demo observations.
- `QUALIFIED`: approved research/forward criteria pass with dated evidence.

## Universal Completion Gate

A task cannot become `VERIFIED_COMPLETE` without:

- documented acceptance criteria;
- positive and negative tests;
- regression test result;
- evidence of relevant failure paths;
- documentation update;
- commit hash/evidence reference.

## Economic Boundary Gate

Anything that can create/modify/close an order additionally requires:

- HALT enforcement test;
- duplicate request test;
- concurrent request test;
- restart/crash recovery test;
- ambiguous broker-response test;
- partial-fill/reconciliation test where applicable;
- demo-account attestation;
- proof no live account is authorized.

## Risk Gate

Test at minimum:

- NaN/Inf and invalid numeric values;
- unknown actions;
- BUY/SELL geometry;
- minimum R:R policy;
- boundary values for per-trade/account exposure;
- daily/weekly drawdown semantics after ADR approval;
- concurrent reservation behavior;
- HALT before and during request lifecycle;
- source/account identity preservation.

## Outcome/ML Gate

No profitability dataset may include `UNKNOWN` or `UNVERIFIED` labels. Outcome-label edge cases must be covered before model training. All time-series splits are chronological/walk-forward. Scaling/feature transforms fit on training windows only.
